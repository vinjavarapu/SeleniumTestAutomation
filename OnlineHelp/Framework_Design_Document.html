Selenium Framework Design

This document describes the framework currently present in this repository: a Maven, Java, Selenium WebDriver, and TestNG sample that exercises the public SauceDemo practice site. It is not evidence of measured customer performance, release readiness, or production reliability.

Current capabilities

  • Page objects, TestNG suites, listener based ExtentReports, screenshots, and parallel method execution.
  • -Psmoke selects smoke tests and -Pregression selects regression tests.
  • retryCount configures additional attempts after the first attempt. It defaults to 0 retries, or 1 total attempt.
  • Pull requests, pushes to main, and nightly scheduled runs execute smoke tests on Chrome and Firefox and regression tests on Chrome.
  • QA runs by default. The STAGING_BASE_URL repository variable adds staging. CI disables retries and uploads run-specific test reports.
  • CI logs browser and driver versions. Set CHROME_VERSION to a specific version to control Chrome regression runs; unset, the workflow uses the stable channel.

Configuration and test data

Checked-in SauceDemo credentials and checkout values are public demo fixtures. Private credentials should be supplied through runtime environment variables or CI secrets, never checked into property files. TESTDATA_<KEY> environment variables override fixture values, for example TESTDATA_VALID_USERNAME.

Interpreting estimates

Any ROI, pass-rate, timeline, execution-time, or reliability figures in portfolio materials are illustrative planning estimates. This repository contains no measured baseline or longitudinal run data to substantiate them. Actual outcomes depend on the target application, environment, browser versions, and test data.

Local commands

mvn clean test -Psmoke
mvn clean test -Pregression
mvn clean test -Pregression -DretryCount=2

The last command allows up to three total attempts. Keep retries disabled for release-gating CI and review first-attempt failures whenever diagnostic retries are enabled.
