Design choices

Tests stay readable

Test classes hold scenario intent and assertions. Page classes expose focused actions and read-only state.

Browser setup is centralized

BaseTest creates and closes browsers, captures failure screenshots, and records test outcomes.

Waits follow application state

Explicit waits check page navigation, cart counts, and checkout transitions instead of fixed sleeps.

Data stays outside test logic

Public demo credentials and customer values are read from a classpath properties file.

What the suite validates

Independent browser tests cover high-value customer flows and the supporting checks that keep them reliable.

Login and session

Valid and rejected credentials, required-field errors, locked-out account behavior, password masking, logout, refresh, and direct inventory access after logout.

Inventory and products

Product names, prices and images; product detail content; return navigation; alphabetical and price sorting; responsive viewport checks.

Cart behavior

Add and remove products, badge consistency, multiple products, item name/description/price/quantity, continue shopping, and repeated add/remove actions.

Checkout and orders

Required customer fields, special and long input values, overview line items, calculated subtotal/tax/total, cancellation, successful completion, and Back Home.

Navigation and keyboard checks

Side menu, All Items and About links, app-state reset, browser back/forward, keyboard tab traversal, and single- and multi-item end-to-end purchase flows.

Reporting and failure evidence

  • Log4j console and rolling-file logs under target/logs/
  • Extent report at target/extent-reports/
  • Automatic failure screenshots under target/screenshots/
  • TestNG and Surefire XML/text reports under target/surefire-reports/
